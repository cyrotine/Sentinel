# Spec: Surface Real Diffs in UI

## Overview

Currently the Code Changes section in `agent-run-detail.tsx` renders only the filename and a text description for each change. The `patch` field — a full unified diff string generated by the `DeveloperAgent` — exists on every `CodeChange` object in the API response but is never read or displayed.

This feature renders `CodeChange.patch` as a proper syntax-highlighted diff viewer, replacing the plain text list. The output looks like a GitHub diff: removed lines in red, added lines in green, hunk headers in gray, file path in the header bar, and a copy-to-clipboard button on each block.

This is a frontend-only change. No backend modifications are required.

Why it matters: the current UI cannot answer the question "what exactly did Forge change?" A user reviewing an agent run sees only summaries like "Corrected typo from Mane to Name" with no way to verify. Surfacing the actual patch makes the pipeline output inspectable and trustworthy.

## Depends On

No previous unimplemented features. The `patch` field is already present on every `CodeChange` object returned by `GET /api/agent-runs/{runId}`.

## User Story

As a developer reviewing an agent run, I want to see the exact unified diff for each file change so that I can verify what Forge modified before accepting the pull request draft.

## Frontend Changes

### New Component: `DiffViewer`

**File:** `apps/web/src/components/agents/diff-viewer.tsx`

A pure React component. No external diff-parsing library. The unified diff format is simple enough to parse with string operations:

```
Lines starting with "---"     → old file header  (skip rendering, shown in block header)
Lines starting with "+++"     → new file header  (skip rendering, shown in block header)
Lines starting with "@@"      → hunk header      (gray, smaller text)
Lines starting with "-"       → removed line     (red background, red text)
Lines starting with "+"       → added line       (green background, green text)
Lines starting with " "       → context line     (normal)
Empty lines                   → render as context
```

Props:
```typescript
interface DiffViewerProps {
  filePath: string
  patch: string
  description: string
}
```

Visual structure per change block:
```
┌─────────────────────────────────────────────┐
│ 📄 src/index.html                  [Copy ✓] │  ← file header bar (dark bg)
│ Corrected typo from Mane to Name            │  ← description (gray)
├─────────────────────────────────────────────┤
│ @@ -12,5 +12,5 @@                           │  ← hunk header (gray bg)
│   <form>                                    │  ← context line (white)
│ -   <input placeholder="Mane">              │  ← removed line (red bg)
│ +   <input placeholder="Name">              │  ← added line (green bg)
│   </form>                                   │  ← context line (white)
└─────────────────────────────────────────────┘
```

Copy-to-clipboard behaviour:
- Clicking "Copy" copies the raw `patch` string to the clipboard.
- Button label changes to "Copied!" for 1500ms then reverts.
- No toast library needed — in-component state is sufficient.

Empty patch handling:
- If `patch` is an empty string or only whitespace, render a fallback:
  `<p className="text-xs text-gray-400 italic">No diff available</p>`

---

## Implementation Rules

- TypeScript strict mode. No `any`.
- `DiffViewer` must be a Client Component (`"use client"`) because it uses `useState` for the copy button.
- Parse the diff with a single-pass line iterator — no regex-heavy approach needed.
- Tailwind only for styling. No inline style objects.
- Line numbers are optional for this phase — do not add them unless they fall out naturally. Do not block the feature on line number rendering.
- The component must handle malformed or partial diffs gracefully — never throw, never crash the page.
- `agent-run-detail.tsx` is already a Client Component. No change needed there.

## Architecture Impact

**Affected systems:** Frontend only (`apps/web`).

**Dependencies introduced:** None.

**Scalability:** The diff viewer renders line-by-line. For the MVP target (30–40 line HTML files), diffs will be tiny. No virtualisation needed at this stage.

**Future extensions:**
- Line numbers can be added to `DiffViewer` as a future enhancement without changing its interface.
- When Phase 6 (GitHub PR creation) is implemented, the `DiffViewer` component can be reused in a PR preview panel.
- The component is self-contained and can accept a `collapsed` prop in the future to show diffs in a collapsed state by default for large changesets.

---

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| LLM generates a malformed or partial unified diff | Medium | `DiffViewer` must never throw on bad input — always render what it can, fall back to the raw patch as a `<pre>` block if parsing produces zero lines |
| Patch string is empty for some agent runs | High (existing runs) | Empty patch fallback is a DoD item — render `"No diff available"` |
| Copy to clipboard fails in non-HTTPS context | Low | Wrap `navigator.clipboard.writeText` in try/catch; silently ignore failure in dev |
